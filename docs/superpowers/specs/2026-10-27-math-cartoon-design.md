# 초등 수학 원리 탐구 웹앱 설계 (1~3학년, 6학년까지 확장)

## 의도와 이유

초등 1~3학년 학생이 수학 원리를 답으로 듣기보다 스스로 깨닫도록 돕는 웹앱을 만든다. 단계 하나가 원리 하나를 담당한다. 학생은 단계를 자유롭게 골라 들어가고, 각 단계에서 원리를 보여주는 만화 설명과 연습 문제를 함께 본다.

## 목표

- 학생이 단계 목록에서 원하는 단계를 자유롭게 선택한다.
- 각 단계는 원리를 보여주는 만화 설명과 그 원리를 쓰는 연습 문제로 구성된다.
- 만화는 답을 바로 말하지 않고, 장면 속 캐릭터의 질문으로 학생이 직접 생각하게 한다.
- 각 장면에서 학생은 캐릭터의 질문에 대한 선택지를 골라야 다음 장면으로 넘어간다.
- 만화를 끝까지 본 뒤 연습 문제로 넘어간다.
- 연습 문제는 객관식이다. 단계 안에서 쉬운 것부터 순서대로 나온다. (제안)
- 문제를 틀리면 같은 원리의 만화 장면을 힌트로 보여주고, 힌트를 본 뒤 같은 문제를 다시 풀게 한다.
- 단계 완료 기준은 그 단계의 모든 문제를 맞히는 것이다.
- 6학년까지 확장할 수 있도록, 단계 내용(원리, 만화 장면, 문제 규칙)은 코드가 아니라 데이터 파일에 둔다.

## 비목표

- 로그인, 계정, 서버 저장
- 점수 경쟁과 순위표
- 교사나 학부모용 관리 화면

## 실패 조건

- 만화가 답을 그대로 알려줘서 학생이 생각할 필요가 없어진다.
- 학생이 객관식 보기를 찍어서 넘어갈 수 있다. 완화책은 틀리면 힌트를 본 뒤 다시 풀게 하고, 모든 문제를 맞혀야 완료되게 하는 것이다.
- 6학년 단계를 추가할 때 화면 코드를 고쳐야 한다.

## 제약

- 빌드 도구 없이 HTML·CSS·JavaScript 정적 파일만으로 동작한다.
- GitHub Pages에 배포한다. 학생은 배포된 주소로 접속한다.
- 대상은 초등 1~3학년이며, 화면 글은 한글이다.
- 단계 내용은 데이터 파일로 분리되어 있어야 한다.
- 브라우저는 `file://`에서 `fetch`로 JSON을 읽지 못하므로, 로컬 확인은 간단한 정적 서버로 한다. (내가 정한 것)

## 접근 방식

- **A. 정적 웹 (채택)**: 설치가 필요 없고, 단계 내용을 데이터로 분리하면 6학년까지 추가하기 쉽다. 단점은 만화 장면과 애니메이션이 많아지면 파일이 흩어지기 쉽다는 점이다.
- **B. React + Vite (기각)**: 화면을 컴포넌트로 나눠 관리하기 좋지만, `npm` 설치와 개발 서버가 필요하고 1~3학년 교육용 앱으로는 무겁다. 사용자가 A를 선택했다.

## 1차 범위 (사용자 결정)

- 엔진(화면 흐름, 선택지, 힌트, 완료 판정, 데이터 로딩)과 시범 2단계를 만든다.
- 시범 단계는 1번 묶음 세기, 4번 받아올림이 있는 덧셈으로 한다. (내가 정한 것)
- 나머지 12단계는 같은 형식으로 2차에 추가한다.
- 애니메이션은 1차에 넣지 않는다.
- 만화 대본, SVG 그림, 문제 규칙은 제가 작성한다.

## 콘텐츠 구조 (제안)

단계마다 데이터 파일 하나를 둔다. 각 파일에는 다음이 들어간다.

- 단계 번호, 학년, 영역, 원리 이름, 원리 한 줄 요약
- 만화 장면 목록: 장면 그림 설명, 캐릭터 대사, 학생에게 묻는 질문
- 문제 생성 규칙: 범위, 자릿수, 문제 개수
- 힌트 장면: 어떤 틀린 답에 어느 만화 장면을 보여줄지

## 화면 흐름 (제안)

단계 목록 → 단계 진입 → 만화 장면 → 연습 문제 → 결과와 다음 단계

## 파일 구조 (제안)

```
index.html          단계 목록
step.html           단계 화면 (만화와 문제)
css/style.css
js/                 화면 동작 코드
data/steps/*.json   단계별 내용, fetch로 읽는다 (6학년까지 추가)
assets/             만화 그림 (SVG)
```

## 사용자가 정한 것

- 만화 진행: 장면 안에서 선택지를 골라야 다음 장면으로 넘어간다.
- 문제 형식: 객관식.
- 틀린 문제는 힌트 장면을 본 뒤 다시 푼다.
- 단계 완료: 모든 문제를 맞힌다.
- 1차 범위와 제작 주체: 위 "1차 범위" 절과 같다.
- 배포: GitHub Pages.

## 내가 정한 것 (확인 필요)

- 단계는 잠금 없이 자유롭게 고른다.
- 정답은 선택 즉시 확인해 준다.
- 힌트 장면은 단계마다 하나씩 두고, 오답 유형별 힌트는 2차 이후로 미룬다.
- 힌트를 다시 봐도 되는 횟수는 제한하지 않는다.
- 기기는 PC와 태블릿을 모두 지원하도록 터치 입력이 가능하게 만든다.
- 진행 상태는 브라우저 `localStorage`에 저장한다. 없어도 화면은 정상 동작해야 한다.
- 만화 그림은 SVG로 직접 그린다.
- 데이터는 JSON으로 두고 `fetch`로 읽는다. GitHub Pages에서는 동작하고, 로컬 확인은 `python -m http.server` 같은 정적 서버로 한다.

## 아직 정하지 않은 것

- 객관식이라 찍기가 가능하다. 틀린 뒤 재도전 방식이 찍기를 충분히 막는지는 시범 단계로 확인해야 한다.
- 1~3학년 단계 구성과 순서를 교육과정 목차와 대조해 확정하기.
- 저장소를 GitHub에 올리는 방법(새 저장소 생성, Pages 설정 방법)은 배포 단계에서 정한다.
